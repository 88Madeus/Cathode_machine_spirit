# CLAUDE.md — контекст проекта для Claude Code

Программа управляет накалом катода LaB₆ установки ПР-8 через программируемый источник
ITECH IT6012D-300-150 (300 В / 150 А / 12 кВт, SCPI по LAN или USB). Ошибка здесь может
стоить катода: таблетка LaB₆ хрупкая и трескается от резкого изменения тока. Поэтому
главное в любой правке — не нарушить инварианты безопасности ниже.

## Устройство

- Один файл `pr8_cathode_app.py` — намеренно: в лаборатории переносят и запускают один
  файл. Разбивать на пакет только по просьбе владельца репозитория.
- Разделы файла по порядку:
  1. настройки и пределы: `DEFAULTS`, `LIMITS`, `RATE_MAX`, `MAX_STEP_A`, словарь `SCPI`,
     `validate_settings`, `load_settings` / `save_settings`, `log_dir`, `keep_awake`;
  2. кривые: `up_segments`, `down_segments`, `curve_points`;
  3. транспорт: `ItechIO` (pyvisa), `SimIO` (модель нагревателя), `Supply` (повторы,
     ресинхронизация ответов `_realign`, проверка формата ответов), `explain_comm_error`;
  4. экспорт журнала в Excel: `export_session_xlsx`;
  5. движок `Engine` — рабочий поток;
  6. окно: `run_gui` → класс `App` (Tkinter + matplotlib).
- Потоки. `Engine._run` в своём потоке каждые `dt` = 0,5 с опрашивает прибор и ведёт
  уставку (`_step` → `_safety` → `_limits` → `_overpower` → `_advance`). Окно не трогает
  прибор: шлёт команды через `Engine.send(...)` (исполняются в потоке движка методами
  `_cmd_*`), читает `Engine.snap` (словарь, пересоздаётся каждый цикл) и `history()`.
  Результаты фоновых задач окна возвращаются в поток Tk через очередь `uiq`.
- Фазы движка — константы `PH_*`; `RAMPING` (идёт движение), `FALLING` (вниз и авария).
- Единственная точка, где программа меняет ток прибора, — `Engine._set_curr`.

## Инварианты безопасности — не нарушать

Подробности, причины и тесты на каждый пункт — `docs/design_decisions.md`.

1. Ток меняется только через `_set_curr`; одна команда — не больше `MAX_STEP_A` (0,5 А).
   Никаких `CURR` в обход.
2. При подключении прибор не меняется: только `SYST:REM` и чтение. Горячий катод
   подхватывается без скачка. `VOLT:LIM` приводится к настройке только по команде
   оператора и только если это не даст скачка тока (`_sync_vlim`).
3. Выход выключается только: оператором («Выключить выход сразу» с подтверждением),
   при обрыве цепи (ток ≈ 0 два отсчёта подряд) и в конце снижения до 0. Потеря связи
   выход не выключает — источник сам держит последнюю уставку.
4. Пока источник ограничивает ток (упор в предел напряжения, предел прибора), рост
   запрещён, уставка держится не выше тока + `LIM_MARGIN`; снижение (▼, авария) идёт.
5. Прежде чем менять уставку из-за расхождения тока и уставки — сверить `CURR?` с прибором.
6. После сбоя связи запросы отправляются только после `_realign`. Первый отсчёт после
   сбоя или подхвата — только наблюдение. Защиты, которые меняют ток или выход, —
   по двум отсчётам подряд; одиночные неправдоподобные отсчёты отбрасываются.
7. ▲ никогда не ведёт вниз, ▼ — вверх (`up_segments` / `down_segments` пустые).
8. Скорости не больше `RATE_MAX` (10 А/мин), опрос 0,2–1 с — это держит `validate_settings`.
9. Совместимость с Python 3.8; тексты окна и журнала — по-русски и понятны оператору.

## Как проверять изменения

```
pip install -r requirements-dev.txt
pytest -q                     # ≈ 4 мин; окно — нужен дисплей (Linux: xvfb-run -a pytest)
pytest -q -m "not gui"        # без окна
python tools/fake_itech.py --speed 60   # эмулятор прибора: LAN 127.0.0.1:30000
```

- Найдена ошибка, опасная для катода, — сначала тест, который её воспроизводит
  (модели неисправностей прибора — `tests/faults.py`), потом исправление.
- Время модели ускорено (`sim_speed` 400–1500). Короткоживущие состояния (например,
  `comm_fail`) ловить по событиям в журнале, а не по `snap`.
- Тесты не пишут в рабочую папку: фикстура `isolated` подменяет `SETTINGS_PATH` и `LOG_DIR`.
- Поменялись сообщения или поведение, видимые оператору, — обновить
  `docs/test_plan.md`, повысить `__version__`, дописать `CHANGELOG.md`.

## Не проверено на реальном приборе (ждём результатов испытаний)

- Команды SCPI IT6000D (словарь `SCPI` в начале файла): `FUNC CURR`, `VOLT:LIM`,
  `VOLT:LIM?`, форматы ответов `OUTP?` и `FUNC?`, поведение `SYST:LOC`.
- Порт Socket (по умолчанию 30000) и расхождение «ток − уставка» у конкретного прибора.
- Поведение защит во время горящего разряда.

Ход испытаний и таблица результатов — `docs/test_plan.md`.

## Данные установки

- Нагреватель: ≈ 20 мОм холодный; при 88 А — 5,09–5,22 В, ≈ 450–460 Вт, 58–59 мОм.
- Кривая разогрева и остывания взята из ручных нагревов 30.09–06.10.2026:
  `docs/heating_rates.md`. Разогрев 0 → 88 А ≈ 54 мин, остывание ≈ 46 мин.
- 05.10 при 70 → 80 А R упало на 39 % — контакт трубок охлаждения с корпусом;
  отсюда защита «R падает при росте тока».
- Цепь накала при разряде сидит под потенциалом катода (−100…−115 В) — связь по LAN.
